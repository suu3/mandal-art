# 검증과 제약사항

검증 기준일: 2026-10-29 (한국 시간). 시점별 작업 로그 대신 현재 구현의 검증 범위를 정리한다.

## 자동 검증

`npm run check`는 FSD 의존성 경계, 테스트, TypeScript, 운영 빌드를 순서대로 검사한다. 확인한 결과는 테스트 11개 파일·55개 통과, 타입·빌드 통과다. 의존성 보안 검사에서 알려진 취약점은 검출되지 않았다. 검사 결과는 이후 코드·의존성과 공개 보안 공지에 따라 달라질 수 있다.

| 범위 | 검증 내용 |
| --- | --- |
| API와 데이터 격리 | 실제 workerd/D1과 서명된 세션으로 다른 계정의 보드 조회·수정·삭제 차단 |
| 저장 경합 | revision 조건부 수정, 동시 저장 충돌 409, 원자적 목표 교체 |
| 생성 제한 | 계정별 보드 상한, 동시 생성, 삭제 우회 방지, 구·신 API의 공통 제한 |
| 입력 검증 | 잘못된 목표 트리·중복·순환·revision·날짜·본문 크기 거부 |
| 마이그레이션 | 기존 보드와 revision 보존, 이전 저장 경로와 호환 |
| 공유 캐시 | 한 번의 조회를 표·목록·진행률에서 공유, 저장 결과 동시 반영 |
| 편집과 오류 복구 | 실패 시 낙관적 체크 복구, 편집 초안 보존, 계정 변경 시 캐시 제거 |
| 기기 데이터 | 손상된 저장소 원본 보존·복구, JSON 백업 왕복 |
| 정적 응답 | 루트·보드 SPA 경로·개인정보 페이지의 보안 헤더 |

## 브라우저와 배포 확인

- 기기 보드 제목 저장·완료 체크 후 새로고침 시 유지됨을 확인했다.
- 하위 목표 진입·추가·수정·삭제, JSON 다운로드와 잘못된 JSON 가져오기 시 원본 보존을 확인했다.
- 375px 화면에서 문서 가로 넘침이 없고, 다크 모드가 새로고침 후 유지됨을 확인했다.
- 운영에서 보드 화면과 PNG 다운로드를 확인했고, 이미지 변환 중 CSP 위반은 없었다.
- 운영 정적 응답의 보안 헤더, 익명 보드 API 요청 401, OAuth 공급자 활성화 설정을 확인했다.
- 원격 DB migration 적용 상태와 Worker 배포 성공을 확인했다. 공급자 활성화 설정만으로 실제 로그인 왕복 성공을 보증하지 않는다.

## 제약과 추가 검증 범위

- 실제 Google/GitHub 로그인 왕복과 새 배포 버전의 로그인 계정 CRUD는 이번 검증에 포함하지 않았다. 배포 후 실제 계정으로 별도 확인한다.
- A/B 계정 격리는 로컬 D1 통합 테스트로 검증했으며 운영 사용자 데이터를 바꿔 검사하지 않았다.
- 대규모 동시 접속, 다계정 악용, DDoS, 모든 API의 rate limit, 운영 백업 복원, PWA 최초 오프라인 실행은 별도 검증 대상이다.
- 생성 제한은 계정별 활성 보드 수와 생성 속도에 적용된다. 삭제된 데이터의 누적 보관 용량까지 제한하지는 않는다.
- 보드는 논리 삭제하므로 영구 삭제 요청과 백업 보관 정책은 별도로 운영해야 한다.
- 이미지 업로드와 과거 Neon/Supabase 계정의 자동 병합은 지원하지 않는다. 이미지가 포함된 과거 백업은 별도 이전이 필요하다.
- 비밀키 패턴 검사와 의존성 검사는 알려진 패턴·공지 범위에 한정된다. 보안 문제가 전혀 없다는 보증은 아니다.
